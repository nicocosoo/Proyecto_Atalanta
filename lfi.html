LFI (Local File Inclusion)

Mouad Tenbihi 05/11/2020
Volver a Noticias

Actualmente hay muchas maneras de atacar páginas web. En este artículo vamos a ver cómo atacar la vulnerabilidad LFI (Local File Inclusion). Esta técnica consiste en incluir ficheros locales, es decir, archivos que se encuentran en el mismo servidor con este tipo de fallo. Es diferente a Remote File Inclusion (RFI), que incluye archivos alojados en otros servidores.

Esto se produce como consecuencia de un fallo en la programación de la página al filtrar inadecuadamente lo que se incluye al usar funciones en PHP para incluir archivos. Un atacante podría así incluir archivos del servidor con información crítica, como el archivo de contraseñas /etc/passwd en sistemas Linux.

Cómo detectar la vulnerabilidad LFI

1. Agregando un valor ilógico a la variable en la URL: Si al modificar el parámetro se obtiene un error como Warning: main() o Warning: include(), es un indicio de que la página puede ser vulnerable.

2. Ver código PHP vulnerable:

<?php include $_GET['pagina']; ?>

Si el archivo incluido proviene directamente de una variable GET sin filtrar, es vulnerable.

Técnicas de explotación

1. Mediante función include: Navegar por los directorios del servidor usando ../ para acceder al archivo /etc/passwd.

2. Utilizando el User-Agent: Modificar el header User-Agent con código PHP malicioso mediante Burp Suite para inyectar una webshell.

3. Mediante metadatos de imagen: Subir una imagen .jpg cuya cabecera haya sido modificada con jhead para incluir código PHP, y luego realizar el include.

4. Ataque LFI con diccionario: Usando herramientas de fuzzing como dirb, wfuzz o gobuster con un diccionario de rutas susceptibles de LFI para encontrar respuestas 200 válidas.

Cómo mitigar la vulnerabilidad LFI

1. Hardcodear el archivo incluido:

<?php include('pagina.php'); ?>

Así se cierra la puerta de entrada sin depender de variables de usuario.

2. Deshabilitar allow_url_fopen y allow_url_include en el archivo php.ini. Muy pocas aplicaciones necesitan esta funcionalidad.

3. Validación estricta de la entrada del usuario: Filtrar y validar cualquier parámetro que se use para incluir archivos.

En conclusión, la vulnerabilidad LFI puede ser muy peligrosa pero es bastante sencilla de mitigar con buenas prácticas de programación.
