Hacking con Unicode

Por Daniel Monzón

Vamos a hablar sobre Unicode, qué es y cómo usarlo en ejercicios de Red Team o pentests.

Unicode (al contrario de lo que parece) no es un tipo de encoding, es una base de datos que mapea cualquier símbolo (glifo) existente a un número único llamado code point (al cual se le asigna también un nombre único). Por ejemplo, «A» se mapea a U+0041 y «a» se mapea a U+0061.

Existen caracteres Unicode desde U+000000 hasta U+10FFFF (hay más de un millón de símbolos). Unicode divide todos esos posibles símbolos en «planos», el más conocido es el BMP (Basic Multilingual Plane) que va desde U+0000 hasta U+FFFF. Existen 16 planos más, denominados «planos astrales».

Unicode se puede usar en JavaScript y la manera de representarlo es con secuencias de escape:

// Secuencias de escape Unicode (para BMP):
\u0041\u0042

// Secuencias de escape Unicode ECMA Script 6:
\u{41}       // BMP
\u{1F4A9}    // Planos "astrales"

Los caracteres Unicode de los llamados planos «astrales» también se pueden representar como surrogate pairs en UTF-16. Existe además una feature de Unicode llamada normalización (NFC, NFD, NFKD, NFKC), cuya idea es normalizar algunos code-points para acabar teniendo el mismo carácter.

¿Qué podemos hacer como atacantes con Unicode?

1. Phishing con dominios similares (IDN Homograph Attack)

Podemos usar herramientas como EvilURL para buscar nombres de dominios parecidos a los que queremos suplantar para hacer phishing, aprovechando caracteres Unicode visualmente idénticos a los del alfabeto latino.

2. Inyecciones SQL

Se puede usar Unicode para bypassear funciones de sanitización de input custom, aprovechando la normalización de caracteres Unicode. También podemos usar Unicode para terminar strings en MySQL si el charset no es utf8mb4.

3. WAF bypass

Los WAFs suelen estar configurados para detectar payloads de XSS en ASCII. Representar los mismos payloads con caracteres Unicode equivalentes puede evadir esas reglas de detección.

4. Path traversal

También podemos usar Unicode para conseguir path traversals que tengan restricciones de caracteres. Por ejemplo, usando %c1%1c y %c0%af en vez de ../, o %c0%ae%c0%ae como representación hexadecimal de ...

5. Extensiones de archivos

Se pueden «falsificar» extensiones de archivos con RTLO (U+202E, Right-to-Left Override), además de bypassear whitelists y blacklists tradicionales con extensiones equivalentes en Unicode.

6. CRLF y Open redirects

Los caracteres \u2028 y \u2029 pueden tener el mismo uso que %0a y %0d en ataques CRLF injection. Payload de ejemplo:

%E5%98%8A%E5%98%8DSet-Cookie:%20test

7. Account takeover

Si sabemos que existe un usuario admin en una aplicación web, hay veces que al registrar un usuario con caracteres Unicode equivalentes (como ÃđᛖᎥｎ) podemos acabar sobreescribiendo sus datos y tomando el control de su cuenta. A veces también es posible abusar de esto en procesos de password reset.

8. Errores de memoria

Muchos programas tienen problemas para manejar caracteres Unicode, lo que da lugar a errores tipo stack buffer overflow, heap-based overflow, out-of-bounds read/write, integer overflow, UAF y otros. En Unicode existen desde los típicos caracteres de control hasta caracteres vacíos (U+2800 y U+200C), e incluso «colisiones» al convertir de mayúsculas a minúsculas que pueden acabar siendo fallos de seguridad.

Herramientas útiles

  • Homoglyph Attack Generator — para encontrar caracteres equivalentes en Unicode
  • codepoints.net — base de datos de code points Unicode
  • EvilURL — generador de URLs homográficas para phishing

Hay un sinfín de cosas curiosas y útiles que pueden hacerse con Unicode, seguramente muchas más de las que yo he podido encontrar. Espero que os haya gustado.

— Daniel Monzón —
